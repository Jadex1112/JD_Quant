# Chapter 4 – Acronyms & Abbreviations

## 4.1 Purpose

This chapter establishes the standardized acronyms and abbreviations used throughout the JD Quant AI documentation suite.

The objective is to ensure that all stakeholders—including software architects, quantitative researchers, AI engineers, backend developers, frontend developers, DevOps engineers, security engineers, quality assurance teams, project managers, and future maintainers—interpret technical terminology consistently.

All acronyms defined in this chapter shall have identical meaning throughout every documentation volume unless explicitly superseded by a future revision.

## 4.2 Documentation Standards

The first occurrence of an acronym within a document shall be written in its expanded form followed by the acronym in parentheses.

Example:

> Software Requirements Specification (SRS)

Subsequent occurrences may use only the acronym.

All engineering documentation shall follow this convention.

## 4.14 Naming Conventions

To ensure consistency across documentation and implementation, the following naming conventions shall be adopted:

| Item | Convention |
|---|---|
| Classes | PascalCase |
| Interfaces | PascalCase |
| Methods | camelCase |
| Variables | camelCase |
| Constants | UPPER_SNAKE_CASE |
| Database Tables | snake_case |
| Database Columns | snake_case |
| Configuration Keys | dot.notation |
| Event Names | dot.notation |
| API Endpoints | kebab-case |
| File Names | kebab-case |
| Directory Names | lowercase |

These conventions are normative for documentation. Language-specific implementation standards may extend them while preserving consistency.

## 4.15 Acronym Governance

The acronym list defined in this chapter is the authoritative reference for the JD Quant AI project.

Any new acronym introduced in future documentation shall:

- Be unique within the documentation suite.
- Have a single unambiguous meaning.
- Be added to this chapter through the project’s documentation change-control process.
- Remain backward-compatible unless formally deprecated.
- Be referenced consistently across all volumes, diagrams, interface specifications, architecture documents, and implementation artifacts.

Deprecated acronyms shall not be reused for unrelated concepts to preserve historical traceability and documentation integrity.
